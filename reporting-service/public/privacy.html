Help improve Launchpad

Usage statistics, software inventory and error reports have three independent switches. Reports you submit yourself are separate. Launchpad works with all background reporting switched off.

What is sent

Reports contain a random support ID, Launchpad version, selected application, an operation or problem category, a timestamp and a limited set of technical results. Optional context may include up to 20 recent structured steps, public package versions, coarse duration, and whether a restart or recovery copy is available. Application and package versions require software inventory consent; the Launchpad version is basic context.

They contain no names, VATSIM CIDs, email addresses, passwords, Hoppie codes, file paths, profile contents, browser sessions, screenshots, diagnostic ZIPs, raw exception messages or stack traces. This version has no free-text report field.

Three separate background choices

  • Usage: recorded Launchpad sessions, launch actions, feature use, setup routes, GNG package sources and display preferences. This does not measure controlling time or network connections.
  • Software inventory: presence, public version metadata and version source for a fixed list of known applications and EuroScope plugins. This uses the configured locations; it is not a search of your personal files. It does not send paths, plugin settings, file contents or a list of other software. A plugin being present does not prove it is enabled or running. On desktop versions that support it, an additional Detailed DLL inventory choice includes all DLLs found within a bounded scan of configured plugin folders. It sends recognized product identities, readable versions, SHA-256 file fingerprints, copy counts and whether copies are current or staged. Unrecognized DLLs are included by fingerprint without their filenames. Fingerprints identify identical file contents across installations and may distinguish custom builds. Existing reporting choices do not enable this extra option. Incomplete scans are marked.
  • Errors: structured operation failures using a fixed list of error codes, without raw exception text.

Nothing is sent until you explicitly save your choices. Closing the prompt sends nothing. You can change each choice independently in App settings. Switching a category off clears its unsent queue; it cannot recall records already received. Inventory can be shared with usage switched off, and is counted as a separate sample.

A manual report works with all three switches off. You review its exact contents before choosing Send. An unsuccessful submission can be retried or saved locally; an abandoned report is never silently sent later.

Your support ID

A random UUID links reports from the same Launchpad data installation across application updates. It is not derived from your account, hardware or VATSIM details. Sharing it with the maintainer lets them find your reports, so the records are pseudonymous, not fully anonymous.

Generate new support ID in App settings starts a new identifier and clears pending reports, locally saved sent copies and correlation context. It does not delete records already received. The ID is a lookup reference, not a password or permission to access records.

Copies on your PC

In desktop versions that include it, Help → Last sent reports shows a readable summary and the JSON of the latest confirmed send for usage, software inventory, automatic errors and manually submitted problem reports. Copies start with versions that include this view; it cannot reconstruct older sends. Refresh reads local storage and sends nothing.

At most one confirmed copy of each type is kept within the same 1 MiB reporting storage limit as the pending queue. Copies stay until replaced, the support ID is regenerated or reporting data is explicitly reset. Switching reporting off or clearing pending records retains these past copies. They are local records, separate from the service retention periods below.

Storage and access

Records are private to the owner and passkey-authenticated team members whom the owner has granted access. Each account has separate page permissions, enforced by the corresponding APIs. Support access includes records linked to a support ID; it is not a public lookup. They do not automatically become GitHub issues. Raw usage, inventory and error records expire after 30 days. Aggregate usage and error counts without support IDs may be kept for up to 12 months; software inventory is not added to those historical aggregates. Closed reports expire after 90 days; unresolved reports are reviewed rather than silently discarded to make space.

There are fixed storage and request limits. If the service cannot accept a report, Launchpad offers retry or local save. Reporting failures never prevent installation, updates or recovery.

The service necessarily sees a connection address in transit. It must not persist raw addresses, identifying headers, query strings or report bodies in access logs. Hosting and backup retention must follow the published operational policy; deletion is not a promise of immediate removal from existing backups.

Backoffice accounts

Invited team members use a chosen username and a passkey. The service stores their username, permissions, passkey public credential, bounded sign-in state and access-management records. It does not receive the passkey private key or device biometrics. Invitation secrets expire after ten minutes and are stored only as hashes. These administrative accounts are separate from the random support IDs used in Launchpad reports. The owner can disable access or reset an account for a new passkey.
