Help improve Launchpad

Usage statistics, software inventory and error reports have three independent switches. Reports you submit yourself are separate. Launchpad works with all background reporting switched off.

What is sent

Reports contain a random support ID, Launchpad version, selected application, an operation or problem category, a timestamp and a limited set of technical results. Optional context may include up to 20 recent structured steps, public package versions, coarse duration, and whether a restart or recovery copy is available. Application and package versions require software inventory consent; the Launchpad version is basic context.

They contain no names, VATSIM CIDs, email addresses, passwords, Hoppie codes, file paths, profile contents, browser sessions, screenshots, diagnostic ZIPs, raw exception messages or stack traces. This version has no free-text report field.

Three separate background choices

  • Usage: recorded Launchpad sessions, launch actions, feature use, setup routes, GNG package sources and display preferences. This does not measure controlling time or network connections.
  • Software inventory: presence, public version metadata and version source for a fixed list of known applications and EuroScope plugins. This uses the configured locations; it is not a search of your personal files. It does not send paths, plugin settings, file contents or a list of other software. A plugin being present does not prove it is enabled or running.
  • Errors: structured operation failures using a fixed list of error codes, without raw exception text.

Nothing is sent until you explicitly save your choices. Closing the prompt sends nothing. You can change each choice independently in App settings. Switching a category off clears its unsent queue; it cannot recall records already received. Inventory can be shared with usage switched off, and is counted as a separate sample.

A manual report works with all three switches off. You review its exact contents before choosing Send. An unsuccessful submission can be retried or saved locally; an abandoned report is never silently sent later.

Your support ID

A random UUID links reports from the same Launchpad data installation across application updates. It is not derived from your account, hardware or VATSIM details. Sharing it with the maintainer lets them find your reports, so the records are pseudonymous, not fully anonymous.

Generate new support ID in App settings starts a new identifier and clears pending reports and correlation context. It does not delete records already received. The ID is a lookup reference, not a password or permission to access records.

Storage and access

Records are private to the authenticated maintainer. They do not automatically become GitHub issues. Raw usage, inventory and error records expire after 30 days. Aggregate usage and error counts without support IDs may be kept for up to 12 months; software inventory is not added to those historical aggregates. Closed reports expire after 90 days; unresolved reports are reviewed rather than silently discarded to make space.

There are fixed storage and request limits. If the service cannot accept a report, Launchpad offers retry or local save. Reporting failures never prevent installation, updates or recovery.

The service necessarily sees a connection address in transit. It must not persist raw addresses, identifying headers, query strings or report bodies in access logs. Hosting and backup retention must follow the published operational policy; deletion is not a promise of immediate removal from existing backups.
